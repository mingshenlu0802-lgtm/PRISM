# 让朋友看到你的内容：一步一步

## 先说清楚问题出在哪

你现在把网址发给朋友，他打开会看到**演示数据** —— 不是你编辑过的内容。

原因很简单：你的内容**存在你自己电脑的浏览器里**。网站是「静态」的，
意思是它只有一堆现成的页面文件，没有一个地方能放大家共用的数据。
你在控制端改的每一个字，都只写进了你这台电脑，别人拿不到。

```
你的电脑                          朋友的电脑
┌──────────────┐                 ┌──────────────┐
│ 你编辑的内容  │   ← 互不相通 →   │  演示数据     │
└──────────────┘                 └──────────────┘
```

**解决办法**：在中间加一个大家共用的数据库。

```
你的电脑  ┐                      ┌  朋友的电脑
          ├→  共用数据库  ←──────┤
其他编辑  ┘                      └  其他朋友
```

免费，十五分钟，只做一次。做完之后：

- **朋友有链接就能看，不用登录、不用注册、什么都不用装**
- 你改了内容，朋友刷新就看到
- 想收更新通知的人可以**顺手用邮箱登录**（收一封信，点链接，不用设密码）
- 你指定的少数人能**编辑**内容，其他人只能看

> **一句要说在前面的话：链接就是全部的门禁。**
> 谁拿到链接谁就能看——朋友转发给别人，别人也能看。
> 网站已经设了「不要收录我」，正经的搜索引擎不会把它放进搜索结果，
> 但这挡不住转发。
> 如果你要的是「**没被我批准的人打不开**」，那是另一套做法——
> 跟我说一声，把成员名单改成读取门槛就行，五分钟的事。

# 第一步：注册 Supabase 并建一个项目

**约 5 分钟。**

1. 打开 <https://supabase.com>，点右上角 **Start your project**。
2. 用邮箱或 GitHub 账号注册。
3. 注册完会让你建项目，点 **New project**。
4. 填三样：

   | 栏位 | 填什么 |
   |---|---|
   | **Name** | `prism`（随便，跟你的名字无关就行） |
   | **Database Password** | 点旁边的 **Generate a password**，然后**复制存好** |
   | **Region** | 选离你或朋友最近的（东亚选 Northeast Asia / Southeast Asia） |

   > 那个数据库密码这个网站用不到，但丢了以后想直连数据库会麻烦，存进密码管理器就行。

5. 点 **Create new project**。

**等一两分钟**，它在给你开一台数据库。屏幕上会转圈，等它转完。

---

# 第二步：建表和权限规则

**约 3 分钟。这一步决定了谁能看、谁能改。**

**不用去仓库里找任何文件** —— SQL 就在你的控制端里，一个按钮就能复制。

1. 打开你的网站 → 右上角 **控制端** → **编辑** → **账号与同步**。
2. 往下找到 **「让朋友也能看」**，点开里面的 **「四步接上」**。
3. 第 2 步那里有一个输入框：**填你自己的邮箱**
   （就是你以后登录网站、管理内容用的那个）。
4. 点 **「复制建库 SQL」**。

   > 你的邮箱已经被自动填进 SQL 里了，不用再手动改任何一行。

5. 回到 Supabase，左边点 **SQL Editor** → **New query**。
6. **粘贴**（Ctrl/⌘ + V）。
7. 点右下角 **Run**（或 Ctrl/⌘ + Enter）。
8. 看到绿色的 **Success. No rows returned** 就成了。

> **复制按钮没反应？** 浏览器有时会拦剪贴板。
> 那一步下面有个「复制不了？点开手动选中这一段」，点开，全选，复制。

> **报错了？** 这段 SQL 重复跑多少遍都没问题，不会弄坏已有的东西 ——
> 确认粘贴完整（从 `-- PRISM` 开头到最后一行），重跑一次。

> **想自己看看这段 SQL 做了什么？** 它在仓库的 `supabase/schema.sql`，
> 或者直接看控制端里展开的那一段。简单说：建 5 张表，
> 然后写死几条规则 —— 内容谁都能读，写入必须是站长或编辑，
> 成员名单只有成员看得到、只有站长能改。

---

# 第三步：把网站连上数据库

**约 2 分钟。**

## 3.1 拿到两串字符

1. Supabase 左下角点 **Project Settings**（齿轮图标）。
2. 左边选 **API**。
3. 这一页上有两样要复制的：

   | 名字 | 长什么样 |
   |---|---|
   | **Project URL** | `https://abcdefghijk.supabase.co` |
   | **Project API keys** 下面的 **anon** **public** | 很长的一串，`eyJ...` 开头 |

   > **这两串是公开的，不是密码。** 把它们提交进仓库、印在网页上都没关系 ——
   > 光有它们什么也做不了。能读到什么、能改什么，完全取决于你登录之后是谁，
   > 以及第二步建好的规则。这是 Supabase 的设计方式。

## 3.2 粘进控制端

1. 打开你的网站 → 右上角 **控制端**。
2. 点 **编辑** → **账号与同步**。
3. 往下找到 **「让朋友也能看」**。
4. 把两串分别粘进两个框。
5. 点 **「在这台电脑上连起来」**。

页面会刷新，这时网站是空的 —— 因为数据库里还没有内容。

**接着登录一次**：右上角点 **登录**，输入你在第二步里填的那个邮箱，
点 **发登录链接**，去邮箱收信，点里面的链接。回来之后你就是站长了，
右上角会出现 **控制端** 入口。

## 3.3 让朋友也连得上（关键，别漏）

刚才那一步只让**你这台电脑**连上了。朋友打开你的网址，他的浏览器里什么都没有，
还是连不上。所以还要把配置发布出去：

1. 还在 **编辑 → 账号与同步**。
2. 先确认下面 **同步到 GitHub** 那一节的 **GitHub token** 已经填好
   （没填的话，按那一节的说明先弄一个）。
3. 回到「让朋友也能看」，点 **「发布出去，让朋友也能连」**。
4. 等一两分钟，GitHub 会自动重新发布网站。

> **这一步的作用**：把那两串字符写进网站自己的文件里，
> 这样任何人打开你的网址，浏览器都能知道该连哪个数据库。
> **不做这一步，朋友看到的还是演示数据。**

# 第四步：把内容放进去

第一次连上时数据库是空的。两个办法把内容放进去：

- **控制端 → 找新闻 → 开始搜集** —— 搜到的会直接存进数据库。
- **控制端 → 编辑 → 内容** —— 手动一条条加。

> 如果你之前在本地模式下攒了内容想搬过来：先在**连数据库之前**，
> 到「账号与同步 → 下载文件」导出一份留底。目前还没有一键导入，
> 需要的话在控制端的 Claude 里说一声「把我下载的内容文件导进数据库」。

# 第五步：分享给朋友

**直接把网址发给他就行。** 他打开就能看，什么都不用做。

## 什么时候才需要加名单

只有两种情况：

**① 你想让某个人也能改内容。**
控制端 → 编辑 → 账号与同步 → 「谁能进这个网站」→
填他的邮箱 → 点 **加为编辑**。
然后让他去网站右上角登录一次（输邮箱 → 收信 → 点链接），他就有编辑权限了。

**② 你想以后能给某些人发更新通知。**
让他自己在网站右上角登录一次就行 —— 登录之后你就知道他是谁了。

> **不加名单的人照样能看内容。** 名单管的是「谁能改」和「给谁发信」，
> 不是「谁能看」。

## 朋友那边会经历什么

**只想看**：打开网址，看内容。结束。

**想收通知或要编辑权限**：点右上角 **登录** → 输邮箱 → 收信
（**记得看垃圾邮件**）→ 点链接 → 回到网站。
不用设密码，不用 Google 账号，不用装任何东西。

## 后续管理

- **改身份**：在名单里那一行的下拉框里选，立刻生效。
- **踢出去**：点那一行的 **×**，他下次打开就进不来了。
- **站长那一行删不掉也降不了级** —— 这是防止你把自己锁在外面。

# 常见问题

**朋友说没收到信。**
先看垃圾邮件。Supabase 免费额度下发信有频率限制（每小时几封），
短时间内反复点会被限流，等几分钟再试。

**朋友说他进不了控制端。**
控制端只有站长和编辑能进。要给他编辑权限，在名单里把他加成「编辑」，
让他重新登录一次。只是看内容的话根本不需要进控制端。

**我自己也进不去了。**
说明第二步最后那行的邮箱填错了。回 Supabase → SQL Editor，跑这一句
（把地址换成你的）：

```sql
insert into public.members (email, role, name, added_by)
values (lower('你的邮箱@gmail.com'), 'owner', '站长', 'fix')
on conflict (email) do update set role = 'owner';
```

**网站突然连不上了，说数据库暂停。**
免费项目**连续 7 天没人访问会被自动暂停**。去 Supabase 后台点一下
**Restore project** 就恢复了，**数据一条都不会丢**。

**能不能让某条内容暂时不给人看？**
控制端 → 内容 → 那一条 → **下架**。下架可恢复；**永久删除**才不可逆。

**能不能整个站暂时关掉？**
控制端最下面「危险操作」→ **暂停显示**。成员打开会看到暂停提示，内容还在。

**内容是公开可读的，那别人能不能拿到我朋友的邮箱？**
不能。**成员名单和编辑日志是锁着的** —— 名单里是朋友们的邮箱地址，
那是他们的个人信息。只有登录过的成员能看到名单，只有站长能改。
新闻和研究可读，名单不可读，这是两条不同的规则。

**那没登录的人能不能改我的内容？**
不能。写入一律要求是站长或编辑，由数据库强制执行，
改浏览器里的代码没有用。

**我想改成「只有我批准的人才能看」。**
可以。在 `supabase/schema.sql` 里把三条 `for select using (true)` 换成
`using (public.can_read())`，再补回 `can_read()` 那个函数，重跑一次 SQL。
或者直接跟我说一声。

**我想退回原来的样子。**
把 `public/prism-config.json` 里的 `url` 和 `anonKey` 清空，重新发布。
数据还在 Supabase 里，随时能连回来。

# 之后可以做的：给成员群发邮件

成员表里已经有一个 `notify` 开关，默认打开。要真的发信（比如「今天更新了 5 条」），
需要再接一个发信服务 —— Resend 免费额度每月 3000 封，对这个规模够用。

这一步还没做。要做的时候，在控制端的 **Claude** 标签里说一句
「接上 Resend，让我能给成员群发更新通知」就行。
