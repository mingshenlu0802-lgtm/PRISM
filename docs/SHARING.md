# 让朋友看到你的内容：一步一步

## 先说清楚问题出在哪

你现在把网址发给朋友，他打开会看到**演示数据** —— 不是你编辑过的内容。

原因很简单：你的内容**存在你自己电脑的浏览器里**。网站是「静态」的，
意思是它只有一堆现成的页面文件，没有一个地方能放大家共用的数据。
你在控制端改的每一个字，都只写进了你这台电脑，别人拿不到。

```
你的电脑                          朋友的电脑
┌──────────────┐                 ┌──────────────┐
│ 你编辑的内容  │   ← 互不相通 →   │  演示数据     │
└──────────────┘                 └──────────────┘
```

**解决办法**：在中间加一个大家共用的数据库。

```
你的电脑  ┐                      ┌  朋友的电脑
          ├→  共用数据库  ←──────┤
其他编辑  ┘                      └  其他朋友
```

免费，十五分钟，只做一次。做完之后：

- 你改了内容，朋友刷新就看到
- 朋友用**邮箱**登录（收一封信，点链接，不用设密码）
- **只有你加进名单的人能打开网站** —— 名单之外的人一个字都看不到
- 你决定谁只能看、谁能编辑

---

# 第一步：注册 Supabase 并建一个项目

**约 5 分钟。**

1. 打开 <https://supabase.com>，点右上角 **Start your project**。
2. 用邮箱或 GitHub 账号注册。
3. 注册完会让你建项目，点 **New project**。
4. 填三样：

   | 栏位 | 填什么 |
   |---|---|
   | **Name** | `prism`（随便，跟你的名字无关就行） |
   | **Database Password** | 点旁边的 **Generate a password**，然后**复制存好** |
   | **Region** | 选离你或朋友最近的（东亚选 Northeast Asia / Southeast Asia） |

   > 那个数据库密码这个网站用不到，但丢了以后想直连数据库会麻烦，存进密码管理器就行。

5. 点 **Create new project**。

**等一两分钟**，它在给你开一台数据库。屏幕上会转圈，等它转完。

---

# 第二步：建表和权限规则

**约 3 分钟。这一步是整件事的核心 —— 它决定了谁能看、谁能改。**

1. Supabase 页面**左边**找到 **SQL Editor**（图标像一个数据库）。
2. 点 **New query**。
3. 打开你仓库里的 `supabase/schema.sql` 这个文件，**从头到尾全选复制**。
4. 粘贴到 SQL Editor 里那个大输入框。
5. **改最后一行**。往下拉到底，你会看到：

   ```sql
   values (lower('CHANGE-ME@example.com'), 'owner', '站长', 'setup')
   ```

   把 `CHANGE-ME@example.com` 换成**你自己的邮箱**：

   ```sql
   values (lower('你的邮箱@gmail.com'), 'owner', '站长', 'setup')
   ```

   > **为什么必须手动改这一行？**
   > 数据库的规则是「只有名单上的人能读，只有站长能改名单」。
   > 那第一个人从哪来？只能从这里插进去一次。这一行就是把你自己设成站长。
   > 改错了也不要紧，回来重跑一遍就行。

6. 点右下角 **Run**（或按 Ctrl/⌘ + Enter）。

7. 看到绿色的 **Success. No rows returned** 就成了。

> **报错了怎么办？** 最常见的是只复制了半个文件。
> 回到第 3 步，确认从第一行 `-- PRISM` 一直复制到最后一行。
> 这个文件重复跑多少遍都没问题，不会弄坏已有的东西。

---

# 第三步：把网站连上数据库

**约 2 分钟。**

## 3.1 拿到两串字符

1. Supabase 左下角点 **Project Settings**（齿轮图标）。
2. 左边选 **API**。
3. 这一页上有两样要复制的：

   | 名字 | 长什么样 |
   |---|---|
   | **Project URL** | `https://abcdefghijk.supabase.co` |
   | **Project API keys** 下面的 **anon** **public** | 很长的一串，`eyJ...` 开头 |

   > **这两串是公开的，不是密码。** 把它们提交进仓库、印在网页上都没关系 ——
   > 光有它们什么也做不了。能读到什么、能改什么，完全取决于你登录之后是谁，
   > 以及第二步建好的规则。这是 Supabase 的设计方式。

## 3.2 粘进控制端

1. 打开你的网站 → 右上角 **控制端**。
2. 点 **编辑** → **账号与同步**。
3. 往下找到 **「让朋友也能看」**。
4. 把两串分别粘进两个框。
5. 点 **「在这台电脑上连起来」**。

页面会刷新，然后出现一个**输入邮箱的登录页**。
输入你在第二步里填的那个邮箱，点 **发登录链接**，去邮箱收信，点里面的链接。

**你就进来了。** 这时网站是空的 —— 因为数据库里还没有内容。

## 3.3 让朋友也连得上（关键，别漏）

刚才那一步只让**你这台电脑**连上了。朋友打开你的网址，他的浏览器里什么都没有，
还是连不上。所以还要把配置发布出去：

1. 还在 **编辑 → 账号与同步**。
2. 先确认下面 **同步到 GitHub** 那一节的 **GitHub token** 已经填好
   （没填的话，按那一节的说明先弄一个）。
3. 回到「让朋友也能看」，点 **「发布出去，让朋友也能连」**。
4. 等一两分钟，GitHub 会自动重新发布网站。

> **这一步的作用**：把那两串字符写进网站自己的文件里，
> 这样任何人打开你的网址，浏览器都能知道该连哪个数据库。
> **不做这一步，朋友看到的还是演示数据。**

---

# 第四步：把内容放进去

第一次连上时数据库是空的。两个办法把内容放进去：

- **控制端 → 找新闻 → 开始搜集** —— 搜到的会直接存进数据库。
- **控制端 → 编辑 → 内容** —— 手动一条条加。

> 如果你之前在本地模式下攒了内容想搬过来：先在**连数据库之前**，
> 到「账号与同步 → 下载文件」导出一份留底。目前还没有一键导入，
> 需要的话在控制端的 Claude 里说一声「把我下载的内容文件导进数据库」。

---

# 第五步：加朋友

**控制端 → 编辑 → 账号与同步 → 「谁能进这个网站」**

1. 在输入框里填朋友的邮箱。
2. 选一个按钮：

   | 按钮 | 他能做什么 |
   |---|---|
   | **加为「只能看」** | 看全部内容。改不了任何东西。**大多数朋友用这个** |
   | **加为编辑** | 能改新闻、发内容、启动搜集。**不能**增删成员 |

3. 把网站地址发给他。

## 朋友那边会经历什么

1. 打开你的网址 → 看到一个写着「这是一个只给朋友看的站点」的页面
2. 输入他的邮箱 → 点 **发登录链接**
3. 去邮箱收信（**记得让他看垃圾邮件**）→ 点链接
4. 自动跳回网站，进来了

**全程不用设密码，不用 Google 账号，不用装任何东西。**

## 后续管理

- **改身份**：在名单里那一行的下拉框里选，立刻生效。
- **踢出去**：点那一行的 **×**，他下次打开就进不来了。
- **站长那一行删不掉也降不了级** —— 这是防止你把自己锁在外面。

# 常见问题

**朋友说没收到信。**
先看垃圾邮件。Supabase 免费额度下发信有频率限制（每小时几封），
短时间内反复点会被限流，等几分钟再试。

**朋友点了链接，页面说「这个账号还不在名单里」。**
邮箱对不上。让他把那个页面上显示的地址原样发给你，照着加一次。
常见原因是他用了另一个邮箱，或者你打字时漏了一个字母。

**我自己也进不去了。**
说明第二步最后那行的邮箱填错了。回 Supabase → SQL Editor，跑这一句
（把地址换成你的）：

```sql
insert into public.members (email, role, name, added_by)
values (lower('你的邮箱@gmail.com'), 'owner', '站长', 'fix')
on conflict (email) do update set role = 'owner';
```

**网站突然连不上了，说数据库暂停。**
免费项目**连续 7 天没人访问会被自动暂停**。去 Supabase 后台点一下
**Restore project** 就恢复了，**数据一条都不会丢**。

**能不能让某条内容暂时不给人看？**
控制端 → 内容 → 那一条 → **下架**。下架可恢复；**永久删除**才不可逆。

**能不能整个站暂时关掉？**
控制端最下面「危险操作」→ **暂停显示**。成员打开会看到暂停提示，内容还在。

**别人能不能绕过登录，直接读数据库？**
不能。所有表都开了 row-level security：不在名单里的账号，**一行都读不到**。
这是数据库层面的规则，不是网页上的判断 —— 改浏览器里的代码没有用。

**我想退回原来的样子。**
把 `public/prism-config.json` 里的 `url` 和 `anonKey` 清空，重新发布。
数据还在 Supabase 里，随时能连回来。

# 之后可以做的：给成员群发邮件

成员表里已经有一个 `notify` 开关，默认打开。要真的发信（比如「今天更新了 5 条」），
需要再接一个发信服务 —— Resend 免费额度每月 3000 封，对这个规模够用。

这一步还没做。要做的时候，在控制端的 **Claude** 标签里说一句
「接上 Resend，让我能给成员群发更新通知」就行。
