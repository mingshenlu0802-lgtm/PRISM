# 分享给朋友：完整步骤

目标：网站不对外公开，只有你请进来的人能看；他们用邮箱登录，不用密码，
不用 Google；你决定谁只能看、谁能编辑；以后还能给他们群发邮件。

时间：约十五分钟，只做一次。全程免费。

---

## 先弄清楚现在是什么状态

网站有两种运行方式，打开时自动判断：

| | 本地模式（现在） | 共享模式（做完这篇之后） |
| --- | --- | --- |
| 内容存在哪 | 你这台电脑的浏览器里 | 一个共用的数据库 |
| 朋友打开你的网址看到什么 | **演示数据**，不是你的内容 | 跟你一样的内容 |
| 谁能进 | 谁都能进 | 只有你加进名单的人 |
| 你改了内容，朋友那边 | 看不到 | 刷新就看到，不用你做什么 |
| 权限靠什么把关 | 界面判断（能绕过） | **数据库强制执行**（绕不过） |

**最重要的一句**：现在把网址发给朋友，他看到的是演示数据。
这不是坏了，是静态网站本来就没有一个大家共用的地方。下面就是给它加一个。

---

## 第一步：建数据库（约 5 分钟）

1. 打开 <https://supabase.com>，用邮箱或 GitHub 注册。
2. **New project**。
   - **Name**：`prism`（或任何你喜欢的，跟你的名字无关的）
   - **Database Password**：点它自动生成，**存到密码管理器里**。
     这个密码这个网站用不到，但万一以后要直连数据库会需要。
   - **Region**：选离你或朋友最近的。
3. **Create new project**。等一两分钟，它在给你开一台数据库。

> **关于免费额度**：这个规模的站点远远用不完。
> 唯一要注意的是：**连续 7 天没有任何人访问，免费项目会被暂停**——
> 你在后台点一下就能恢复，数据不会丢。

---

## 第二步：建表和权限规则（约 3 分钟）

1. Supabase 左边选 **SQL Editor** → **New query**。
2. 打开这个仓库里的 `supabase/schema.sql`，**整个文件**复制。
3. 粘进 SQL Editor。
4. **改最后一行**：把 `CHANGE-ME@example.com` 换成**你自己的邮箱**。

   ```sql
   values (lower('你的邮箱@gmail.com'), 'owner', '站长', 'setup')
   ```

   > 为什么必须在这里写死一次：在有第一个成员之前，数据库里谁都读不到东西，
   > 而只有站长能加成员——这是个死循环，所以第一个人得从这里插进去。

5. 右下角 **Run**。看到 `Success` 就成了。

这一步建好了：内容表、成员表、以及**每一条权限规则**。
从这一刻起，谁能读、谁能写由数据库说了算，不是由网页说了算。

---

## 第三步：把网站连上（约 2 分钟）

1. Supabase 左边 **Project Settings**（齿轮）→ **API**。
2. 复制两样东西：
   - **Project URL**，长得像 `https://abcdefgh.supabase.co`
   - **Project API keys** 里的 **anon** **public** 那一串（很长）
3. 打开你的网站 → 控制端 → **编辑 → 账号与同步** → 找到「**让朋友也能看**」。
4. 把两串粘进去，然后：
   - 按「**在这台电脑上连起来**」→ 页面刷新，你会看到登录界面。
     用第二步里填的那个邮箱登录一次。
   - 再按「**发布出去，让朋友也能连**」→ 它把配置写进仓库，网站自动重新发布。
     **不做这一步，朋友打开你的网址还是演示数据。**

> **这两串值是公开的，可以放心提交进仓库。**
> Supabase 的 anon key 本身不授予任何权限——能读到什么、能写什么，
> 完全取决于你登录之后的身份和第二步建好的规则。这是它的设计方式，不是疏忽。

---

## 第四步：把内容搬过去

第一次连上时数据库是空的，网站会显示空的。把你现有的内容放进去：

- 在控制端「**找新闻**」按一次「开始搜集」，新内容会直接存进数据库；或者
- 在「**内容**」里手动新增。

（如果你之前在本地模式下攒了很多内容，先在「账号与同步」里按「下载文件」备份一份。）

---

## 第五步：加朋友

控制端 → **编辑 → 账号与同步** → 「**谁能进这个网站**」：

1. 输入朋友的邮箱。
2. 选身份：
   - **加为「只能看」** —— 大多数朋友用这个。他能看全部内容，改不了任何东西。
   - **加为编辑** —— 他能改新闻、发内容、启动搜集。**不能**增删成员。
3. 把网站地址发给他。

他那边的体验：打开网址 → 看到一个输入邮箱的页面 → 输入你加的那个地址 →
收到一封信 → 点链接 → 进来了。**全程不用设密码。**

> 加错了或者想收回：在名单里点 **×**，他下次打开就进不来了。
> 想把「只能看」升成「编辑」：在他那一行的下拉框里改，立刻生效。

站长那一行删不掉也降不了级——那是防止你把自己锁在外面。

---

## 常见问题

**朋友说没收到信。**
先让他看垃圾邮件。Supabase 免费额度下发信有频率限制（每小时几封），
短时间内反复点会被限流，等几分钟再试。

**朋友点了链接还是说「不在名单里」。**
说明邮箱对不上——注意有没有打错，或者他用的是另一个地址。
让他把登录后页面上显示的那个地址发给你，照着加。

**我想让某条内容暂时不给人看。**
在「内容」里「下架」就行。下架是可恢复的，永久删除才不可恢复。

**我想整个站暂时关掉。**
控制端最下面「危险操作」→「暂停显示」。成员打开会看到暂停提示，内容不会被删。

**数据库会不会被别人翻走？**
不会。所有表都开了 row-level security：不在成员名单里的账号，
一行都读不到。这是数据库层面的规则，不是网页上的判断。

**我以后想退回本地模式？**
把 `public/prism-config.json` 里的两串清空，重新发布即可。
数据还在 Supabase 里，随时能连回来。

---

## 之后：给成员发邮件

成员表里有一个 `notify` 字段，默认打开。要真的群发（比如「今天更新了 5 条」），
需要再接一个发信服务——Resend 的免费额度（每月 3000 封）对这个规模足够。

这一步还没做。要做的时候跟我说一声，在控制端的 Claude 里说
「接上 Resend，让我能给成员群发更新通知」即可。
