# 站长手册

写给不做技术的人看的。照着做就行，看不懂的地方都可以不动。

---

## 一、第一次打开

双击仓库里的 **`PRISM-prototype.html`**，浏览器就打开了整个网站。
右上角有个「控制端」按钮，点进去就是你管理网站的地方。

网站现在装的是**演示数据**：里面的新闻、媒体名字、链接全是编的，只是给你看界面长什么样。
顶上那条「演示数据」的提示，等换成真内容之后会自己消失。

---

## 二、控制端只有两页

### 第一页：找新闻

1. 选**搜哪些地区**。你点名的六个（中国内地、香港、台湾、日韩、美国、欧洲）默认就选好了，
   上面标着「优先」。想只搜这六个，点右上角「只搜优先六个」。
2. 选**搜哪些议题**。默认全选。
3. 按那个大按钮 **开始搜集**。

下面几个设置都有默认值，看不懂可以不动：

| 设置 | 打开会怎样 | 关掉会怎样 |
| --- | --- | --- |
| 找到就直接上线 | 新内容马上出现在公众站，你随时可以删 | 先存成草稿，等你放行 |
| 自动跳过重复的 | 和已有内容很像的就不再加一遍 | 允许重复 |

搜完会告诉你**加了几条**，还会列出**哪些被跳过了、为什么**——不会有东西悄悄消失。
不满意就按「撤销这次搜集」，这一批全部收回。

**用哪个 AI 去找**：找链接是重复劳动，用免费的开源模型就够了，不用花钱。
控制端里的改写固定用 Claude，这个不用你管。

### 第二页：编辑

四个标签，从最常用排到最少用。

**内容** — 点开任意一条新闻就能编辑：

- 改标题、改总结（**想写多长写多长，几百上千字都行，空一行分段**）、改要点
- 加或去掉地区/议题标签（一条可以挂好几个）
- **每一个媒体链接都能单独删掉**，也能自己加新的
- **「设为头条」**：这一条就上首页最上面那个大位置
- 编辑完按「保存」

不想让别人看到，按「**下架**」——内容还在，随时能恢复。
确定不要了，才按「**永久删除**」——这个撤不回来，会先问你一次。

**头条怎么定**

首页最上面那个大位置叫头条，**由你说了算**，不是网站自己挑的。

- 在任意一条上按「设为头条」就行。
- 一次只有一条头条。设了新的，旧的自动让位，「最近编辑」里会写清楚是哪一条让了位。
- 把头条下架，它就自动不再是头条（看不见的东西当不了头条）。
- 你没指定的时候，首页会用最新的一条顶上，不会空着。

**Claude** — 一个聊天框，用大白话说你想改什么：

> 把头条那条扩写成三段，别加新事实 · 香港那条的总结太啰嗦了，砍一半 ·
> 换成深色，字体用宋体 · 把首页那段介绍改得更像人话

它读得到你网站当前的全部内容，能改外观、网站上写的字、新闻的标题总结要点标签，
还能设头条、下架、重新上线。说完就改好了，随时能撤销。

三件它不会做的事：不编造事实和链接（只改写你已有的内容）；不永久删除（最多下架）；
**不改代码**（碰到这类要求会写一份需求让你转给 Claude Code，见第六节）。

要用真的 Claude，得在同一个面板里填一个 Anthropic API key（`sk-ant-` 开头，
在 console.anthropic.com 申请，按用量计费，跟 claude.ai 的订阅是两笔账）。
不填也能用，只是只认得「字大一点」这类固定说法。

**外观** — 手动调字号、主题、强调色、字体、行距，以及网站名称、副标题、首页那段介绍。
这些设置公众站和控制端同时生效，读者自己也能在网站右上角调。

**账号与同步** — 见下面第三、四节。

## 三、让朋友也能看

**要紧的一件事**：现在把网址发给朋友，他看到的是**演示数据**，不是你的内容——
因为内容存在你自己的浏览器里，没有一个大家共用的地方。

要真的分享出去，接一个免费的共享数据库，十五分钟，只做一次。
完整步骤在 **[SHARING.md](SHARING.md)**，控制端「编辑 → 账号与同步 →
让朋友也能看」里也有同样的三步。

接上之后：朋友输邮箱 → 收到一封信 → 点链接就进来了，不用密码不用 Google。
你决定谁只能看、谁能编辑。权限由数据库把关，改浏览器里的代码没用。

## 四、登录和管理员

**看网站不用登录。** 任何人都可以用 Google 账号登录，但登录本身不解锁任何东西——
它只是让网站知道你是谁。

- 站长就是你的 Gmail。它**不写在代码里**——代码里只有它的哈希，
  发布出去的文件里没有任何人的邮箱地址（细节见 [SECURITY.md](SECURITY.md)）。
  只有站长能加管理员、删管理员。
- 加进来的人是**管理员**：能编辑内容、调外观、启动搜集。
- 站长这一行删不掉，这是故意的——不然控制端会变成没人管得了。
- **只有你（和你加的管理员）登录时，账号菜单里才会出现「进入控制端」。**
  别人登录看到的就是一个普通的已登录状态，不会有一个按了会被拒绝的按钮。

**要让登录按钮出现，得先申请一个 Google 客户端 ID。** 控制端「编辑 → 账号与同步」里
写了完整步骤，只做一次，做完就不用再管。

> **先决定域名再申请。** 第三步要填的就是你网站的最终网址。
> 如果你打算换成组织名或自己的域名（见第五节），先换完再来申请，
> 省得回头要改。改也不难，就是在同一个页面加一条来源。

Google 把这块拆成了三个页面，都在「Google 身份验证平台」下面，**顺序不能反**：

| 页面 | 要做什么 |
| --- | --- |
| **品牌塑造**（Branding） | 填应用名称、用户支持邮箱、开发者联系邮箱。其余栏目**全部留空** |
| **受众群体**（Audience） | 用户类型选「外部」，然后点 **发布应用** |
| **客户端**（Clients） | 创建 Web 应用客户端，填「已获授权的 JavaScript 来源」 |

没填完前两页就去建客户端，Google 会拦住你，提示「OAuth 配置不完整，请前往品牌塑造页」。

三个最容易踩的坑：

- **品牌塑造页的「应用主页 / 隐私权政策 / 服务条款」留空。** 一旦填了网址，
  Google 就会要求你再去填「已获授权的网域」并验证域名所有权，平白多两道手续——
  登录本身用不到它们。
- **受众群体页一定要「发布应用」。** 停在「测试」状态的话，只有你手动加进测试用户
  名单的账号能登录，别人一律登不进来。这里只用到姓名、邮箱、头像这类基本信息，
  属于非敏感权限，发布立刻生效，不需要 Google 审核。
- **「已获授权的 JavaScript 来源」只填到域名为止**，比如
  `https://你的用户名.github.io`——不要带后面的路径，也不要结尾的斜杠。
  填错了登录会直接报 `origin_mismatch`。

旁边那串「客户端密钥」用不上，也不要填到网站里任何地方。

> 顺序上，先把 GitHub Pages 打开拿到正式网址，再去申请客户端 ID——
> 因为申请时要填的就是那个网址。

> 在你填好客户端 ID 之前，**控制端是开着的**，页面顶部会明说这件事。
> 这是必须的：没接上登录的时候网站根本不知道谁是谁，这时候拦人既拦不住，
> 又会把你自己锁在唯一能填客户端 ID 的那一页外面。填好之后门就锁上了。

> **要知道的一件事**：这是一个纯静态网站，登录只能挡住界面，挡不住真正懂技术的人。
>
> 但也别慌——他改不了你发布出去的网站。内容真正更新要写回 GitHub，
> 那需要你的 GitHub token，只存在你自己的浏览器里。绕进界面的人能改的
> 只有他自己屏幕上那份副本，刷新就没了。
>
> 要连界面也挡住，需要一个自己的域名加 Cloudflare Access（免费，服务端拦截）。
> 每一步都写在 **[SECURITY.md](SECURITY.md)** 里。

## 五、把内容存回 GitHub

在「编辑 → 账号与同步」里填一个 GitHub token（申请时只需要勾 Contents 的写权限），
按「同步到 GitHub」，当前所有内容就存回你的仓库了。

存的是一个**内容文件**，不是代码，所以同步不会弄坏网站。
token 只留在你自己这台电脑的浏览器里，也不会被写进同步的文件里。

**没有 token 也行**：旁边有「下载文件」，下载下来自己传上去，效果一样。

做「恢复初始内容」这种大动作之前，建议先下载一份备份。

## 六、发布到网上

仓库里已经带好了发布用的配置。你只要做一次：

1. 打开仓库页面 → **Settings**（设置）
2. 左边找到 **Pages**
3. **Source**（来源）选成 **GitHub Actions**

之后每次推送代码，网站会自己重新发布。
发布前会先自动跑一遍检查，不通过就不发布，坏页面上不了线。

### 网址里不要出现你的名字

GitHub Pages 默认给的网址是 `你的账号名.github.io/仓库名/`，账号名里带姓名就会露出来。
三个办法，从最省事到最彻底：

| 办法 | 网址会变成 | 花费 | 说明 |
| --- | --- | --- | --- |
| 建一个**组织**，把仓库转过去 | `prismlens.github.io/PRISM/` | 免费 | 组织名自己起，跟你的个人账号名无关 |
| 改**个人账号名** | `新名字.github.io/PRISM/` | 免费 | 会影响你名下所有仓库的旧链接 |
| 买一个**自己的域名** | `prismlens.org` | 约 ¥80–150/年 | 最干净，也最像一个正经媒体 |

**推荐组合**：先建组织（免费、立刻解决露名问题），以后想要正式域名再加，两者不冲突。

**建组织**：GitHub 右上角头像 → Your organizations → New organization → 选免费方案 →
起一个跟站点有关的名字。然后在仓库的 Settings → 最下面 Transfer ownership，转给这个组织。
转完之后 Pages 要重新按上面三步开一次。

**用自己的域名**：

1. 在任意一家域名商买下域名。
2. 在域名商的 DNS 设置里加四条 A 记录，指向 `185.199.108.153`、`185.199.109.153`、
   `185.199.110.153`、`185.199.111.153`；再加一条 `www` 的 CNAME 指向 `你的组织名.github.io`。
3. 在仓库里新建文件 `public/CNAME`，内容就一行，你的域名，比如 `prismlens.org`。
   <br>（用 Actions 发布时，域名必须写在 `public/CNAME` 里才会被打包进去。）
4. 仓库 Settings → Pages → Custom domain 填上同一个域名，勾上 **Enforce HTTPS**。

DNS 生效通常几分钟到几小时。域名换了之后，**记得回 Google 那边把新域名加进
「已获授权的 JavaScript 来源」**，否则登录会报 `origin_mismatch`。

## 七、发布之后想改东西

分两类，体验完全不同：

**改内容、外观、文案** —— 一句话就好。

控制端「编辑 → Claude」里说「把头条那条扩写成三段」「换成深色」「首页那段介绍改得更像人话」，
说完就改好了，进「最近编辑」，随时能撤销。这类占日常修改的绝大多数。

**改代码**（加新板块、加新页面、改版面结构、加新功能）—— 不是一键，但也不难：

1. 在控制端的 Claude 里把想法说出来。它判断这件事要改代码，就会写一份完整需求。
2. 按「**开成 GitHub issue**」（需要先填好 GitHub token）。
3. 按「**在 Claude Code 里打开仓库**」，跟它说一句「做 issue #12」。
4. 它改完代码推送，GitHub Actions 自动重新构建并发布，一两分钟后网站就更新了。

为什么第 3 步绕不过去：这是一个纯静态网站，页面是提前构建好再传上去的。
改源码、重新构建、重新部署这三件事，浏览器里一件都做不了。
控制端能做到的是把交接做得最省事——需求它写，issue 它开，你只要说一句话。

## 八、出事了怎么办

| 情况 | 怎么办 |
| --- | --- |
| 误删了一条新闻 | 永久删除撤不回来。所以平时不确定就用「下架」 |
| 调乱了外观 | 「Claude」里说「恢复默认外观」 |
| 头条不对 | 去你想要的那一条上按「设为头条」，旧的自动让位 |
| 想加个新板块/新页面 | 在「Claude」里说，它写需求 → 开 issue → 交给 Claude Code（见第六节）|
| 登录报 origin_mismatch | 域名换过了。去 Google 的「客户端」页把新域名加进已获授权的 JavaScript 来源 |
| 搜回来一批不想要的 | 那次搜集下面有「撤销这次搜集」 |
| 想暂时关掉整个网站 | 「编辑」最下面的「暂停显示」（只有站长能按）。内容不会被删 |
| 想全部推倒重来 | 「恢复初始内容」。**先下载备份**，这个撤不回来 |

每一步编辑都记在「编辑」页面下面的 **最近编辑** 里，包括是谁做的、什么时候做的。
